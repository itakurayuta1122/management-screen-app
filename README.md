このプロジェクトは、ユーザー管理画面アプリケーションの開発を通じて、React、TypeScript、およびNext.js (App Router) を活用し、実務でよく使われるCRUD機能（追加・一覧・更新・削除）、検索、ソート機能、useMemoによる最適化、およびLocalStorageによるデータ永続化などを学習・実践するためのアプリケーションです。

## 質問と回答（Q&A）

ここでは、開発中に疑問に思ったことや重要な学びをQ&A形式でまとめています。

### Q: `export default function Home()` は自動で実行される関数ですか？
A: はい。Next.js (App Router) では、`app/page.tsx` で `export default` された関数は、そのパス（ルートURL `/`）へユーザーがアクセスした際、Next.jsによって自動的に呼び出され、UIとして描画（レンダリング）されます。

### Q: Home()関数で全てのコンポーネントが呼び出されて、UserTableにダミーデータを作成して、UserRowにPropsが渡されて、再レンダリングされているのですか？
A: 現在の実装では、`Home`コンポーネントが`UserTable`を呼び出し、`UserTable`がダミーデータを`UserRow`にPropsとして渡しています。ただし、これはコンポーネントの初期描画（レンダリング）であり、State（状態）を管理していないため、現時点では再レンダリングは発生しません。Stateを導入した後に、ユーザーがデータを更新（追加・削除など）した際に自動的に再レンダリングが行われるようになります。

### Q: `addUser` 関数で使われている `newUser` とは？
A: `Omit<User, "id">` 型のオブジェクトです。ユーザーがフォームで入力する「名前・年齢・部署」のみを含んでおり、`id` はシステム側で自動採番するため除外されています。

### Q: `Math.max(...users.map((u) => u.id)) + 1` でIDを生成する仕組みは？
A: 既存のユーザーリストからIDの配列を作成し、その中の最大値に1を足すことで、常に重複しない新しいIDを生成しています。空の場合は `1` を返します。

### Q: `setUsers([...users, userWithId])` で何が起きていますか？
A: 既存のユーザー配列 (`users`) を展開して新しいユーザーを加えた「新しい配列」を作成し、Reactの状態を更新しています。元の配列を直接変更（ミューテート）しないことで、Reactに再レンダリングを促しています。

### Q: `editingUser: User | null;` や `useState<User | null>(null)` とはどういう意味ですか？
A: TypeScriptのユニオン型です。その変数が `User` 型のオブジェクトか `null` のどちらかしか保持できないことを定義しています。初期値として `null` をセットすることで「現在は編集対象が存在しない」状態を表現しています。

### Q: `onUpdateUser: (user: User) => void;` の `()` はどんな意味ですか？
A: 関数型の定義です。`()` はその関数に渡すべき引数（ここでは `User` 型の `user`）を表し、`=> void` は「戻り値を返さない関数」であることを示しています。逆に `onCancelEdit: () => void;` のように `()` 内が空であれば「引数なし」を意味します。

### Q: ユーザー検索機能はどのように実装されていますか？
A: `searchTerm` というStateで検索文字列を管理し、`user.name.toLowerCase().includes(searchTerm.toLowerCase()) || user.department.toLowerCase().includes(searchTerm.toLowerCase())` のように、名前または部署名のいずれかに検索文字列が含まれているかを部分一致で判定しています。`toLowerCase()` を使うことで大文字・小文字を区別せず検索可能にしています。

### Q: `SearchBar` コンポーネントの `value={searchTerm} onChange={setSearchTerm}` はどう動いていますか？
A: Reactの「制御されたコンポーネント」というパターンです。親コンポーネント (`page.tsx`) が State を保持し、`value` で現在の値をコンポーネントへ流し込み、ユーザーの入力変化があった際に `onChange` で親の State (`setSearchTerm`) を更新する仕組みです。

### Q: `UserTable` の props `users={filteredUsers}` とは？コンポーネント側の定義は `users` ですが大丈夫ですか？
A: 大丈夫です。コンポーネントの契約（インターフェース）は `users` という名前でプロップスを受け取ることになっています。親コンポーネント側でその「`users` という箱」に対して、フィルタリング済みのデータ (`filteredUsers`) を渡しています。受け取り側はその中身が全件か絞り込み済みかを意識せず表示に専念できます。

### Q: フィルタリング処理 (`filteredUsers`) とマッピング処理 (`users.map`) はどちらが先ですか？
A: レンダリングのたびに、`.map()` が実行される「前」に `filteredUsers` の計算が行われます。データ（State）に基づいてUIの元データを計算（フィルタリング）してから、それを基にリスト（HTML要素）へ変換するという順序で処理されています。

### Q: 親コンポーネントから関数 (`onEdit`, `onDelete`) を渡すのはなぜですか？
A: 「データ（表示）」と「振る舞い（操作ロジック）」を分離するためです。子コンポーネントは表示に専念し、ロジックは親に集約させることで、子コンポーネントの再利用性が高まり、コードの見通しが良くなります。

### Q: ユーザー削除機能の `setUsers(users.filter((u) => u.id !== userId));` はどう機能していますか？
A: 選択したID以外のデータのみを `filter` で抽出して新しい配列を作り、それを `setUsers` で状態（State）にセットしています。結果として削除対象が除外されます。この State の更新により React が再レンダリングをトリガーし、画面から該当行が自動的に消えます。

### Q: `keyof User` とは？
A: TypeScriptのユーティリティ型です。`User` インターフェースのプロパティ名（"id", "name", "age", "department"）のみを許容する型に変換します。これにより、並び替えのキー指定時に誤ったプロパティ名を指定するミスを防止し、コード補完も効くようになります。

### Q: `if (!sortConfig) return 0;` の `0` は何のために返していますか？
A: JavaScriptの `sort()` メソッドに対する「並び替えを行わない（順序を維持する）」という指示です。まだ並び替え条件が設定されていない初期状態などで、配列の順序を勝手に変更しないようにするために使用しています。

### Q: `direction === 'asc' ? -1 : 1` のような三項演算子はなぜ使われていますか？
A: 昇順（'asc'）か降順（'desc'）かに応じて、`sort()` メソッドに渡す比較数値を反転させるためです。これ一つで昇順・降順の両方の並び替えを動的に切り替えることが可能です。

### Q: `[...filteredUsers]` でフィルタリングした配列を渡しているのはなぜですか？
A: 理由は2つあります。1つ目は、絞り込まれた結果（検索結果）に対して並び替えを行うため。2つ目は、Reactにおいて重要な「Stateの直接変更（ミューテーション）を防ぐ」ためです。スプレッド演算子でコピーを作成することで、元のデータを壊さずに安全に並び替えられた新しい配列を作っています。

### Q: `useMemo` はどういう効果があるの？
A: 計算結果をメモリに記憶し、依存関係（指定した変数の値）が変更されない限り、その計算をスキップして前回の結果を再利用する機能です。レンダリングのたびに重い計算が走るのを防ぎ、アプリケーションの動作を軽くします。

### Q: `useMemo` で、前回の結果がない（初回）場合はどうなりますか？
A: 初回レンダリング時はキャッシュが存在しないため、Reactは必ず計算処理を一度実行します。その結果がキャッシュとして保持され、2回目以降のレンダリングで「依存配列」の中身が同じであれば、次から計算がスキップされる仕組みです。

### Q: 初回レンダリング時に `useMemo` 内の `filter` が空配列で実行される影響はありますか？
A: はい、初期状態の `users` が空であれば、初回は空のリストが表示されます。しかし、その直後に `useEffect` による `localStorage` からのデータ読み込みとステート更新が発生し、再度 `useMemo` が走って正しいデータでリストが再描画されます。この一連の動作は非常に高速なため、ユーザーには違和感なくデータが表示されます。また、検索欄が空の場合は `.includes("")` が常に真を返すため、データが読み込まれた後は全件表示される期待通りの動作になります。

### Q: `localStorage` への保存で初回レンダリング時に空データで上書きされてしまう問題はどう対処しましたか？
A: `isLoaded` という読み込み完了フラグ（boolean）を導入しました。`useState` で `false` から始め、`useEffect` での初回読み込み完了時に `true` にします。保存用の `useEffect` では `if (!isLoaded) return;` というガードを設けることで、初期化中の空データによる上書きを防止しています。

### Q: `useEffect` が増えてコンポーネントが複雑になってきた気がします。どうすればいいですか？
A: Reactの標準的な副作用管理手法ですが、状態が増えると同期処理が複雑になるのが一般的です。解決策として、`useLocalStorage` のような「カスタムフック」にロジックを切り出してコンポーネントから分離する方法があります。これにより、コンポーネント側は単に「値を読み書きする」だけのシンプルな記述になり、保守性が大幅に向上します。

### Q: `requestSort` 関数内の `direction` 切り替えロジックは？
A: 同じ列を連続してクリックした際、現在の状態が昇順なら降順へ、降順なら昇順へと切り替える「トグル」処理を行っています。これにより、ユーザーがクリックするだけで直感的に並び順を変更できるようになっています。

### Q: `useEffect` を使った LocalStorage 読み込みの実装において、`setUsers(initialUsers)` の引数は何ですか？
A: `initialUsers` は、`localStorage` にデータが保存されていない場合にデフォルトとして表示するためのサンプルデータ（定義済み配列）です。`useState` は最初空っぽでスタートし、`localStorage` をチェックした後に中身があればそれを、なければこの `initialUsers` を `setUsers` で読み込むという手順にしています。

### Q: `useEffect` の第2引数の `[]` (空配列) とは何ですか？
A: Reactの「依存配列」と呼ばれるものです。中身を空にすることで「コンポーネントが最初に画面に表示された（マウントされた）時だけ、1回だけ実行する」という意味になります。レンダリングのたびに読み込み処理が走らないようにする、標準的なパターンです。

### Q: この `useEffect` は `setUsers` をきっかけに作動していますか？
A: いいえ、`setUsers` は実行のきっかけではありません。この `useEffect` は「コンポーネントがマウントされた時」をトリガーにして実行されます。
